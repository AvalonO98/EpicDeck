## 1. 焦点与导航（本次重点）

### 1.1 先看懂现有模型

页面结构（`fullscreen.tsx`）：

```
.ed-surface  (Focusable，挂 onGamepadDirection / onButtonDown / onCancel)
├─ NavRow level="header"     返回 | 游戏库 | 下载 | 设置 | spacer | 账号文字 | 刷新
└─ 内容区
   ├─ 游戏库 tab
   │  ├─ NavRow level="toolbar"   全部 | 已安装 | 未安装 | 搜索框 | 排序 | 提示 | 翻页◀ 1/9 ▶
   │  └─ div[data-ed-level="grid"]  5×3 封面
   ├─ 下载 tab   → 单行按钮（暂停/取消/继续/查看）
   ├─ 设置 tab   → 流式表单（ToggleField / Dropdown / TextField / 按钮）
   └─ 详情页     → 顶部"游戏库"chip + 操作行 + 下拉 + 输入框 + 开关 + 信息行
```

三套状态：

1. **`remembered`（geomnav.ts:63）**：我们自己维护的"当前元素"，是导航的唯一起点。
2. **`ownedTarget` / `ownedSettled`（:82-84）**：标记"这一拍是我们移的"，用来识别并回滚 Steam 对同一次按键的插队。
3. **方向键分派（fullscreen.tsx:2697-2803）**：焦点在 `[data-ed-level="grid"]` 内 → `moveFocus`（几何）；否则 → `moveFocusRowCol`（行列）。

方向键**无论是否移动成功都会被 `preventDefault` 吞掉**（:2796-2802），这是"不让 Steam 按 DOM 顺序乱跳"的必要设计，但也意味着：**一旦 `remembered` 失效且 `currentFocused()` 返回 null，键盘就彻底没反应**（因为没人接住事件，也没有回退）。

下表是各页面的焦点现状（✅ 正常，⚠️ 有问题，❌ 坏）：

|---|---|---|---|---|---|

| 游戏库网格 | ✅ 由工具栏/顶栏进入 | ✅（左右到边界翻页） | ❌ 翻页后焦点丢失（1.3） | ✅ | — |
| 详情页 | ✅ 180ms 后落主操作（:2585-2597） | ✅ | ⚠️ 切标签并关掉详情 | ✅ 关详情 | ✅ 按名字找回封面 + 12 帧复检（:2466-2497） |

### 1.2 【P0】点一下空白处，方向键和 A 键就全部失效

**触发（很容易复现）**：打开大屏页后，**用触摸/鼠标点一下任何非可聚焦区域**——封面之间的缝、工具栏的空白、顶栏"设置"和"刷新"之间那段弹性空隙、任意标题文字。然后推摇杆：四个方向都没反应；按 A 也没反应。

**机制**（三处代码串起来）：

1. 点击落点本身不可聚焦 → 浏览器把焦点交给最近的可聚焦祖先，也就是 `.ed-surface` 自己（它是 `Focusable`，带 `tabindex="0"`）。
2. 于是派发 `focusin(target = .ed-surface)` → `fullscreen.tsx:2616` 的处理器调用 `settleFocus()`；`ownedTarget` 为空时走第 3 分支（geomnav.ts:146-149）：`remembered = target`，即**锚点变成了根容器**。
3. 下一次方向键：`moveFocus` / `moveFocusRowCol` 里 `usable(remembered, root)` 因为 `isLeafFocusable(root) === false` 而拒绝（geomnav.ts:222-230），回退到 `currentFocused(root)`。而 `currentFocused` 的三个返回点都要求 `isLeafFocusable`（:244-271），根容器全部不合格；`gpfocus` 候选又因为全页 `noFocusRing` 通常为空 → **返回 null** → `moveFocus` 返回 false。
4. `onRootDirection` 仍然 `preventDefault + stopPropagation`（:2801-2802）→ 按键被吞，什么都没发生。A 分支拿到 `activeElement = .ed-surface`，`el.click()` 也只是点了个没有 onClick 的 div。

**不是每次都触发，取决于 `ownedTarget`**：如果刚才用摇杆移动过，`ownedTarget` 还指着上一张封面，第 2 步会被 `settleFocus` 第 2 分支"拉回原处"（tile 重新获得焦点），但用户的点击被吞掉；**再点第二次**（此时 `ownedSettled = true`）就进入第 3 分支，锚点被污染 → 失联。也就是说：**点两下空白，必定失联**。

**影响**：掌机是触摸屏，点空白/点标题是极常见的动作；失联后只有 B（离开插件）或 L1/R1（切标签，可能再踩 1.3）能救，用户完全不知道发生了什么。

**修复（低风险、可局部）**：

```ts
// geomnav.ts —— 容器永远不得成为锚点
export function settleFocus(target: HTMLElement, root: HTMLElement): HTMLElement {
  // 点击页面根/滚动面板/导航组这类容器时，保持原锚点并还原焦点
  if (!isLeafFocusable(target)) {
    if (remembered && remembered.isConnected && root.contains(remembered)) {
      try { remembered.focus(); } catch { /* ignore */ }
      return remembered;
    }
    const first = root.querySelector<HTMLElement>(CANDIDATE_SELECTOR);
    if (first) { remembered = first; return first; }
    return target;
  }
  ... // 原有三轮判定
}

export function currentFocused(root: HTMLElement): HTMLElement | null {
  // ...原有逻辑...
  // 兜底：不要返回容器；宁可返回页面里第一个可聚焦控件
  if (active && root.contains(active) && isLeafFocusable(active)) return active;
  try {
    return root.querySelector<HTMLElement>(CANDIDATE_SELECTOR);
  } catch { return null; }
}
```

另外建议：`onFocusOut` 兜底（:2521-2563）也顺手覆盖"焦点仍在 root 内但停在容器上"的情况，而不只处理 `body`。

**回归测试**：给 `scripts/test_geomnav.py` 加一条"容器 focusin 不改变锚点"，与现有 8 条同风格即可。

### 1.3 【P0】网格内按 L1/R1 翻页，焦点跟旧封面一起消失

**触发**：光标停在任意封面，按 L1 或 R1 翻页。

**机制**：

- `onRootButton` 的 bumper 分支（fullscreen.tsx:2841-2861）只做三件事：`bumper(delta)`、`preventDefault`、`return`——**没有任何落焦**。
- 网格的 key 包含页码：`key={`${current}-${filter}-${sort}-${query}`}`（:648），换页 = 整个网格 div 重建；tile 又以 `app_name` 为 key，所以**被聚焦的那张封面被卸载**。
- 被聚焦节点被移除后，`activeElement` 变成 `body`，而 Chromium 对"聚焦节点被移除"并不派发 `focusin`（`focusout` 也不保证派发）。于是：
  - 若 `focusout` 兜底触发 → 锚点是脱离文档的旧封面（:2540-2549 会判 `isConnected` 失败）→ 回退到第一个 `.ed-chip`，也就是**光标跳到顶栏"返回"**；
  - 若不触发 → 焦点停在 `body`，`onRootDirection` 收不到事件，**整个页面失联**（与 CHANGELOG 0.9.4 记录的"B 关详情后失联"同一类故障）。

**对比**：用左/右方向键在网格边缘翻页时，代码专门做了落焦（:2732-2744：翻页后把焦点放到新页的 last/first 封面）。**L1/R1 这条路被漏掉了。**

**修复**：把"翻页 + 落焦"抽成一个函数，两条路径共用。

```ts
// fullscreen.tsx
const flipPageAndFocus = (delta: number) => {
  const root = surfaceRef.current;
  const doc = root?.ownerDocument;
  const from = doc?.activeElement as HTMLElement | null;
  const grid = from?.closest?.('[data-ed-level="grid"]') as HTMLElement | null;
  const tiles = grid ? Array.from(grid.querySelectorAll<HTMLElement>(".ed-tile")) : [];
  const idx = from ? tiles.indexOf(from) : -1;
  const col = idx >= 0 ? idx % cols : 0;   // cols 由 viewport.cols 提供，或读 computedStyle
  const moved = gridBumperRef.current?.(delta) ?? false;   // 见 1.4：让 bumper 返回是否真的换页
  window.setTimeout(() => window.setTimeout(() => {
    const r = surfaceRef.current; if (!r) return;
    const next = r.querySelectorAll<HTMLElement>(".ed-tile");
    if (!next.length) return;
    const target = next[Math.min(col, next.length - 1)];
    focusOwned(target); claimFocusRing(target, r);
  }, 0), 0);
  return moved;
};
```

`bumper` 的签名建议改成 `(delta) => boolean`（LibraryTab 里 `next !== current` 时返回 true），这样 1.4 也能一起修。

### 1.4 【P1】首/末页按左/右，光标"原地传送到页面另一端"

**触发**：第 1 页最左列按左；最后一页最右列按右。

**机制**：

- `moveFocus` 在网格里找不到候选 → 返回 false（:2726）。
- 进入 `if (!moved)` 分支，`bumper(delta)` 被调用；但 `goPage`（:514-518）用 `Math.min(pageCount, Math.max(1, current + delta))` 夹住，**第 1 页按左不会换页**。
- 外层仍然 `moved = true`，并无条件把焦点移到 `.ed-tile` 的 `last`（按左）——于是同一页的最后一列被选中。末页按右同理。

**用户感受**：想"到头了，停住"，结果光标从最左瞬移到最右，像是随机跳转。

**修复**：`bumper` 返回是否真的换页；只有换页成功才落焦，否则保持原位（并继续吞掉按键）。

```ts
// LibraryTab.tsx
registerBumper((delta) => {
  const next = Math.min(pageCount, Math.max(1, current + delta));
  if (next === current) return false;
  setPage(next); writeFsUI({ page: next }); return true;
});
```

### 1.5 【P1】L1/R1 切标签后，光标不跟随（0.9.3 修过的问题又回来了）

**触发**：在"游戏库"页按 R1 切到"下载"。

**机制**：`tabOffset`（:2669-2687）里：

```ts
const chip = root.querySelector(`[data-ed-focus-action="tab:${nextId}"]`);
if (!chip) return;   // ← 永远走这里
```

但"聚焦即切页"被删掉之后（CHANGELOG 0.9.3 第 86 行），**没有任何元素再写 `data-ed-focus-action`**——我全仓搜索确认：`src` 里只有注释和这个查询，`dist/index.js` 里也只有 3 处（注释 1 + `getAttribute` 1 + 这个 query 1）。`focusActions` 注册表（:177-194）也因此成了死代码，`runFocusAction` 每次移动都在空跑。

**后果**：内容切了，光标还留在原处；如果原来在网格里，封面卸载 → 又回到 1.3 的焦点丢失路径（落到"返回"或失联）。CHANGELOG 0.9.3 第 295-296 行明确写着"切页后光标会跟到新标签"——**文档与实现已经不一致**。

**修复**：不要再依赖属性，按 TABS 下标取 chip（同时删掉死注册表）：

```ts
const idx = TABS.findIndex((item) => item.id === nextId);
const chips = Array.from(root.querySelectorAll<HTMLElement>("[data-ed-level='header'] .ed-chip"));
const chip = chips[idx + 1];   // +1：第一个 chip 是"返回"
```

更稳的做法是给每个 chip 加 `data-ed-tab={item.id}`，用 `[data-ed-tab="${nextId}"]` 查询。

### 1.6 【P1】可聚焦但不可用的控件：光标会停在"死键"上

四处：

1. **翻页箭头**：`Pager`（:242-295）在 `page <= 1` / `page >= pageCount` 时只是 `opacity: 0.3` 并把 onClick 设为 undefined，**仍然可聚焦**。按 A 毫无反应。
2. **"添加到 Steam"**：未安装时 `data-disabled="true"`，`onClick`/`onActivate` 都是 undefined（:1213-1221），但标签仍写着"添加到 Steam"——用户看到可点、按了没反应，也不知道为什么（实际上"未安装也能加进 Steam"是被产品决定了不支持，但界面没解释）。
3. **`ActionButton disabled`**（components.tsx:584-625）：只加 `data-disabled` 和 opacity，不移出焦点序列。
4. **两处 `.ed-info` 信息行**（:1333、:2317）：为了"让摇杆能滚到"而 `tabIndex={0}`，按 A 什么也不做——这是有意为之，但属于同一类"焦点落在无动作元素上"。

**叠加效应**：按几何模型，从第 5 列封面按"上"会落在翻页键上（实测坐标：封面第 5 列 x≈677，翻页键在 x=805,y=132）。在末页，那就是个死键。

**修复**：

```ts
// Pager
<Focusable tabIndex={page <= 1 ? -1 : 0} aria-disabled={page <= 1} ... />
// 并在 CANDIDATE_SELECTOR 里排除：[tabindex]:not([tabindex="-1"]):not([aria-disabled="true"])
```

`ActionButton` 同理会 `tabIndex={disabled ? -1 : 0}`。注意 `CANDIDATE_SELECTOR` 在 `geomnav.ts:28`，改一处即可让 `moveFocus` / `moveFocusRowCol` / `wrapRow` 同时生效；同时要保证"唯一可聚焦项被禁用"时不会出现"整页无候选"的新死锁（现有 `usable()` 会返回 false，需配合 1.2 的兜底）。

### 1.7 【P1】进设置页"回到顶部 + 落焦首个控件"被早退分支抵消

**代码**：SettingsTab 的挂载 effect（:1706-1737）先算 `first = .ed-group .ed-action, .ed-action`，然后：

```ts
const current = doc.activeElement as HTMLElement | null;
if (current && current !== first && surface.contains(current)) return;   // ← 从 chip 进入时必然命中
```

**现实**：现在进入设置页的**唯一方式**是用 A 点顶栏"设置"chip（或 L1/R1 切过来）。这时 `activeElement` 就是那个 chip——在 surface 内、且不等于 `first`——effect 直接 return：既不 `scrollTop = 0`，也不落焦。

**后果**：

- 上次在设置页滚到"维护"，这次进来仍停在"维护"；
- 按"下"时，几何位置决定目标，可能落到视口中部某一行，而不是页面顶部；
- CHANGELOG 0.9.3（第 126 行）声称"修进入设置页焦点不落在顶部第一个控件"——在主要路径上实际没生效。

**修复**：早退条件改成"用户已经自行移动过焦点"，用我们自己能解释的信号，而不是 `activeElement`：

```ts
// 模块级：每次 showTab 时清零
let navTouchedSinceTab = false;
// onRootDirection 里移动成功后置 true
if (navTouchedSinceTab) return;
```

或者更简单：把 `scrollTop=0` 与落焦从"守卫"里拆出来，只在 `tab` 变化后的第一次渲染执行。

### 1.8 【P2】同一页面里两套模型，上下不是互逆

实测坐标（HANDOFF 7.10，854×534）：

```
返回(15,45 67x32)            刷新(772,45)
游戏库(15,81) 下载(119,81) 设置(209,81)
搜索框(275,125 267x40)              A-Z(550,125 144x40)
全部(15,128 75x33) 已安装(98,128) 未安装(179,128)     翻页(805,132 34x24)
网格第 1 行 (21,180)(185,180)(349,180)(513,180)(677,180)
```

- 从"全部"按**下** → 第 1 张封面（行/列模型：最近 x = 封面中心 95.5，与"全部"中心 52.5 差 43）。
- 从第 1 张按**上** → **"已安装"**（几何模型：封面中心 95.5 离"已安装"中心 134.5 只有 39，比"全部"的 43 更近）。
- 从第 5 列封面按**上** → **翻页键**（A-Z 的横向重叠不足 50%，被严格轮淘汰，翻页键通过）。

所以：**"按下去再按回来"回不到原来的控件**，而且第 5 列上方是分页控件而不是排序控件。这不是算错，而是两套模型拼接的必然结果——但用户的心智模型是"原路返回"。

**修复方向**（任选其一）：

1. 网格内也走 `moveFocusRowCol`（把每行 tile 视为一行，行高就是 tile 高）。代价：失去"同列严格对齐"的搜索感，但上下会严格按行，且与工具栏完全同一套规则；
2. 保留几何模型，但在"上"方向额外记录来源：`showTab`/从工具栏进入网格时记下 `entryElement`，向上时若该元素在当前严格候选里就优先它；
3. 最简单：向上时把严格轮的 `secondary * 0.25` 权重改成"优先选择与当前 tile **水平重叠更大**的候选"，并给工具栏行一个轻微偏好（例如工具栏候选 `score -= 4`）。

建议做 1：模型统一后，1.4、1.6、1.8 三条会一起变简单。

### 1.9 【P2】关闭详情后 12 帧复检会抢走用户的快速输入

`closeDetail` 的落焦路径最后调用 `reverifyFocus(tile, root, 12)`（:2485）——12 帧 ≈ 200ms。`reverifyFocus`（geomnav.ts:159-177）每一帧只要 `activeElement !== expected` 就 `expected.focus()`，**不做归属判断**。

**后果**：B 返回后 200ms 内，用户若已经推了一下摇杆（导航把焦点移到别的封面），下一次 rAF 会把它**拉回原封面**。用户感觉"第一下没反应/跳回来了"。

**修复**：只在"焦点丢了"时拉回，而不是"焦点不是 expected"时：

```ts
export function reverifyFocus(expected, root, frames = 2) {
  const doc = root.ownerDocument;
  const active = doc.activeElement;
  const lost = !active || active === doc.body || active === root || !root.contains(active);
  if (lost) { try { expected.focus(); remembered = expected; } catch {} }
  ...
}
```

帧数建议也降到 3~4 帧。

### 1.10 【P2】输入框里的方向键整体放行给 Steam

`onRootDirection` 第 1 行（:2703）：焦点在 `INPUT/TEXTAREA/SELECT` 时直接 `return`，连 `preventDefault` 都不做。

- 左右放行是对的（要移动光标）；
- **上下放行是错的**：Steam 会按它自己的 DOM 顺序把焦点挪走，落在哪个控件上取决于内部导航树——正是本项目要消灭的"不可预测移动"。

**触发**：库页搜索框、详情页"启动参数"、设置页"自定义路径"。输入完按"下"，光标可能跳到工具栏最右的翻页键（与 HANDOFF 7.10 记录的老毛病同源）。

**修复**：

```ts
if (/^(INPUT|TEXTAREA|SELECT)$/.test(focused0.tagName)) {
  if (button === DIR_LEFT || button === DIR_RIGHT) return;  // 光标移动，放行
  focused0.blur();                                          // 上下：先退出输入
  // 继续走下面的导航逻辑（remembered 仍是该输入框，可用）
}
```

注意 OSK 打开时焦点在另一个窗口，不受影响。

### 1.11 【P2】A 键用 `el.click()`，依赖"组件同时绑了 onClick"

`onRootButton`（:2815-2838）拦截 A、`preventDefault`、然后 `el.click()`。

这不是错，但它建立在一个隐式约定上：**目标元素必须绑了 `onClick`**。Steam/Decky 的 `Dropdown`、`ToggleField`、`DropdownItem` 这类组件的激活入口可能是 Steam 的 `onActivate`（手柄激活路径），而不是 DOM click。页面里我们自己写的 `Focusable` 基本都同时绑了 `onClick + onActivate`，所以现在大概率能用；但这是"靠巧合"而不是"靠契约"。

**建议**：

- 实机验证点：排序下拉、安装位置下拉、LSFG 开关、云存档按钮、`ButtonItem` 登录按钮——每个按一次 A；
- 若要更稳，可以改成"白名单接管"：只有 `el.matches('.ed-chip,.ed-tile,.ed-action,.ed-pager,.ed-loc,[data-ed-own]')` 时才 `preventDefault + click()`，其余交给 Steam 原生的 A 激活。这样 Steam 组件永远走 Steam 的激活路径，而我们自己的按钮仍然"一次一动作"。

顺带：`okGuardRef` 是 250ms 全局防抖（:2824-2829），**两下快速 A（约 200ms 间隔）的第二下会被吞**。掌机连按是常见操作，建议降到 120ms 或只在同一元素上生效。

- 但 `.resume` 清理（:2441-2449）照常执行。
- `install()` 明明在 `main.py:1798-1803` 记了 `install_targets[app_name]`，却没有用它兜底。

**后果（与确认框文案直接矛盾）**：用户点"取消下载"、确认框写着"会删除已下载的进度"，结果几十 GB 的半成品目录原样留在盘上，而 `.resume` 被删 → 重装从 0 开始。磁盘空间没释放，重下还更慢。CHANGELOG 第 176 行把"取消下载时清空该游戏的半成品目录与 `.resume`"写成了已完成功能，0.9.3 第 58-59 行也声称修过"取消下载可能删错目录"——实际是"该删的没删"。

**修复**：取消/暂停时把 `install_targets[app_name]` 与实际目录都纳入候选：

```python
candidates = [install_path]
base = (self.config.get("install_targets") or {}).get(app_name) or ""
if base:
    # legendary 的目录名通常就是 app_name；按 .egstore 核对该目录属于本游戏
    candidate = os.path.join(base, app_name)
    if os.path.isdir(os.path.join(candidate, ".egstore")):
        candidates.append(candidate)
removed_any = False
for cand in candidates:
    safe = self._safe_install_target(app_name, cand)
    if safe:
        shutil.rmtree(safe, ignore_errors=True); removed_any = True
if not removed_any:
    return   # 目录没删掉就不要单独删 .resume，否则用户既占空间又丢续传
```

### 3.4 【Medium】`clear_download_cache` 只检查 `_install_tasks`，漏掉重载后认领的外部下载

`main.py:2453-2484` 的活动判断只看 `_install_tasks`；插件重载后仍在跑的 legendary 只在 `_external_pids`（`main.py:2065-2092`）里。此时「清理下载缓存」会放行，删掉 `<config>/tmp` 里**正在写**的 `.resume`/清单 → 断点续传被破坏。CHANGELOG 第 78 行写的是"有活动下载时拒绝"。

**修复**：`active` 判断把 `_external_pids`、`_install_procs` 和 `_live_progress` 非空项都算上。

### 3.5 【Medium】`install()` / `resume_install()` 不检查外部下载 → 同一游戏可能起第二个 legendary

`main.py:1764-1767` 的守卫只查 `_install_tasks`。重载后下载仍在跑（只存在于 `_external_pids`），此时再下发 install/resume：

- `_install_streaming` 用 `"wb"` 截断 `install-<app>.log`（`main.py:1892-1893`），旧 watcher 从 offset 0 重读垃圾；
- 两个 legendary 同时写同一安装目录，可能损坏 `.resume` 和分片。

**修复**：`install()` 开头加 `if app_name in self._external_pids or app_name in self._install_procs: return {"ok": False, "error": "该游戏正在下载中"}`；`resume_install` 同样先查。

### 3.6 【Medium】`shortcuts.vdf` 读改写无锁 + 固定临时文件名，与线程池写者竞争

- `py_modules/steam.py:340-369`：临时文件名固定为 `path + ".epicdeck.tmp"`。
- `main.py:3215-3225`：`set_setting` 在 `run_in_executor` 里跑 `_sync_launcher_scripts`（内含 `backfill_icons → _save_tree`）；同时安装完成会触发 `_add_to_steam → add_game → _save_tree`（事件循环）。
- 两者"load → 改 → save"交错，共用同一个 tmp：后写者截断前者 / rename 时 tmp 已消失；读改写还会互相覆盖条目。

实测（8 线程并发写 8 条）：**只活下 1 条**，并出现 `PermissionError` / rename 失败。HANDOFF 11.4 的"协程无 await 所以原子"只覆盖了协程路径，漏了 executor 这一条。

**修复**：`steam.py` 加模块级 `threading.Lock`，把每个"load→修改→save"整体包住；临时文件改用 `tempfile.mkstemp(dir=...)` 唯一名 + `os.replace`；callable 侧补 `OSError` 兜底。

### 3.7 【Medium】本地化标题的 `library_patch` 用字符串值，前端按对象读 → 标题补丁静默失效

- `main.py:1517-1526`、`main.py:1553-1560`：`emit("library_patch", {app_name: "中文标题"}, 0)`（值是字符串）。
- `src/store.ts:246-263`：`const p = patch[app_name]; ... title: p.title ?? g.title` —— 字符串没有 `.title`，每行原样返回。

**后果**：Epic 官方中文名 / Steam / Wikidata 补名都不会即时出现，只有下一次 `list_games` 或重载才变中文；`localized_title` 标记也永远不置位。这与 `main.py:1454-1456` 注释"patches are emitted as results arrive so the grid fills in without a reload"正好相反。

**修复**：emit 改成 `{app: {"title": title}}`（前端已支持该形状），两处一起改；或让 store 同时接受字符串。

### 3.8 【Medium】`_pausing` 标记在"任务还没开始就暂停"时永远清不掉

- `main.py:2339-2342`：`pause_install` 先 `self._pausing.add(app_name)` 再 cancel；
- `main.py:1829-1835`：只有 `_run` 收到 `CancelledError` 时才 `discard`。

用户点安装后立刻暂停（task 还没跑第一行），`_run` 的取消处理器不执行 → `_pausing` 永久留着该 app。之后 resume 再"取消"，`_run` 看到旧标记就 emit `"paused"` 并按暂停处理（不清理 partial），UI 显示"已暂停"而用户点的是取消。

**修复**：`install()` / `resume_install()` 开头 `self._pausing.discard(app_name)`；或把"是否暂停"挂在本次任务上下文，而不是全局 set。

### 3.9 【Medium】`_ensure_image_cache` 一次失败就永久缓存 `{}` → 封面与图标从此静默跳过

- `main.py:2526-2534`：`except` 里 `self._image_cache = {}`；
- `main.py:2560-2563`：后续调用看到 `is not None` 直接返回空缓存，不下载也不重试；
- `main.py:3149-3204`：`refresh_artwork` 拿到 0 个更新时返回 `ok: true`，UI 提示"封面已是最新/已补齐"。

**后果**：第一次封面操作时网络抖动，之后所有封面/图标都不再补齐，而"补齐封面"按钮报成功。用户以为修好了。

**修复**：失败时保持 `None`（或记短 TTL）；`refresh_artwork` 在 `_image_cache` 为空时返回 `ok: false` + 警告；区分"确实没有图"和"取不到元数据"。

### 3.10 【Medium】手机登录在 `login_with_code` 抛非 `LegendaryError` 时把状态永久卡在 `"finishing"`

`main.py:566-605`：第 591 行直接 `await self.login_with_code(code)`，没有 try；而 `login_with_code` 内部写 `user.json`（`main.py:496-508` + `config.py:152-163`）可能抛 `OSError`（磁盘满、只读、并发写）。异常冒出后 `_run_phone_login_session` 任务结束，`_login_state` 停在 `{"state":"finishing","message":"已收到授权码，正在登录…"}`。

前端 `login.tsx:163-210` 的轮询只在 `ok / error / timeout` 停止 → **永远转圈**。浏览器登录路径有兜底 `except`（`main.py:944-951`），手机路径没有。

**修复**：把第 591 行包进 `try/except Exception`，失败时把 `_login_state` 置为 `error` 并记日志。

### 3.11 【Medium】三个模块在证书校验失败时回退 `CERT_NONE`，违反 SECURITY.md 的承诺

- `py_modules/protondb.py:113-126`、`py_modules/title_sources.py:65-80`、`py_modules/update_check.py:29-43`；
- `SECURITY.md:36-39` 和 CHANGELOG 0.9.3 第 92 行都写着"不再在证书校验失败时回退 `CERT_NONE`"。

当 certifi 与系统 CA 都不可用（精简 SteamOS、`SSL_CERT_FILE` 指向坏文件）时，商店检索、中文名、ProtonDB、更新检查全部变成**不校验证书**：MITM 可以伪造"最新版本/下载地址"引导用户装假包，或注入错误标题/评级。`legendary_installer.py:60-83` 已经改成 fail-closed，说明这三处是遗漏。

**修复**：统一复用 `legendary_installer._ssl_context()`（失败直接返回空结果），删掉三处 `CERT_NONE` 分支。

### 3.12 【Low】启动脚本把退出码 90 当哨兵，游戏真以 90 退出会被再启动一次

`main.py:2891-2902` 生成的启动脚本用 `[ "$EPICDECK_RC" -eq 90 ] || exit` 判断"shim 没启动游戏"；而 `launchshim.py:291-303` 里任何未捕获异常也会映射成 90。游戏自己以 90 退出（崩溃或自定义退出码）时，脚本会继续走到第二条 `exec legendary launch` → **同一游戏被启动两次**。

**修复**：不要用可被游戏复用的退出码做哨兵；shim 在真正起进程后写一个 marker 文件，脚本只在 marker 不存在时回退。

### 3.13 复核中确认"做得好"的部分（不要改坏）

- CHANGELOG 0.9.4 记录的 `steam.py` 缺 `import re` 回归已确认修复（`py_modules/steam.py:24`，:287 使用正常）。

## 4. 易用性

按"用户在掌机上真实会做的事"排序：

1. **信息密度与滚动**：设置页有 10 个分组、约 40 个可聚焦控件，从顶走到"维护"要按十几次下，没有分组跳转。建议 L1/R1 在设置页做"上一组/下一组"，或左侧加一个分组索引（和"下载设置"跳转同一个机制）。
2. **详情页没有任何游戏介绍/截图**，只有标题、体积、ProtonDB 徽章、游玩时长。用户点开封面最想确认的是"这是什么游戏"，现在只能看名字。建议补 Epic 的 description（`legendary info` 或 store API 都有）。
3. **详情页操作按钮的状态不可解释**："添加到 Steam"在未安装时被禁用（还不解释原因）；"启动游戏"在未加 Steam 时内部会先加再加（有 toast，但用户以为按钮坏了 3 秒）。
4. **下载页没有行焦点**：整行只有右侧两个按钮可聚焦，光标落在"暂停"上时看不出是哪一行的下载。建议整行 `Focusable`（像详情页的 `.ed-loc`），A 进入行内按钮。
5. **破坏性操作的确认框文案很好**（说明会删什么），这是加分项，别改。
6. **每页 15 个封面 + 5×3 很整齐**，但最后一页只有 1~3 个时，网格第二/三行是空的（`alignContent: start` 已经避免拉伸），从最后一页按"下"没有任何反馈。建议在空行区域给一个"已经到底了"的轻提示（或者干脆把翻页键做成唯一出口）。
7. **L1/R1 语义在同一页有三种**（网格=翻页、工具栏=翻页、顶栏/设置=切标签）。保留这个设计可以，但底部按钮提示（`actionDescriptionMap`）是静态文案"上一页 / 上一个标签"，用户按下去才知道是哪种。建议按 `focusLevel` 动态切换提示文案。
8. **登录页**用 QAM 组件渲染在大屏页里，视觉与其它页不一致（白色方框焦点环、PanelSection 的 300px 内边距习惯）。建议给大屏登录页单独一套样式。
9. **首次运行**的"刷新磁盘"按钮没有 busy 反馈，插了 SD 卡后点一下不知道有没有生效。
10. **失败态**（`ErrorBlock`/`WarningBanner`）做得不错，重试按钮可聚焦；但错误横幅出现在工具栏和网格之间，会让网格整体下移，此时如果焦点在网格里，几何坐标全部变化（导航仍然可用，只是视觉跳动）。

## 5. 工程与测试

1. **CI 与 lockfile 不一致**：`.github/workflows/release.yml:37` 用 `pnpm install --frozen-lockfile`，但仓库里**没有任何 lockfile**（`pnpm-lock.yaml` / `package-lock.json` 都不存在，也不在 `.gitignore` 里）。pnpm 在无 lockfile 时会直接报 `ERR_PNPM_NO_LOCKFILE`，`push to main` 的构建检查和 tag 发布都会挂。建议提交 `pnpm-lock.yaml`（或把 CI 改成 `pnpm install --no-frozen-lockfile`）。
2. **本地 `tsc --noEmit` 跑不通**（本机 checkout）：`@decky/api` 的类型引用 `react-router`（package.json 里没有），`react-icons` 没有类型声明 → 7 条错误。CI 上也许因为完整安装能过，但这说明"类型检查"并不是本地可复现的门槛。建议把 `react-router` 加进 devDependencies，并给 `react-icons` 配 `paths` 或忽略。
3. **`regression.py` 的 i18n 覆盖检查有盲区**：只检查含中文的键（:104），所以 `Legendary {0}{1}` 这种纯占位符键漏检。建议改成"所有字面量键都必须有条目，白名单除外"。
4. **`regression.py` 在 Windows 上不可直接运行**：`py_compile` 会写 `__pycache__`、`test_i18n.py`/`test_geomnav.py` 用 `mkdtemp`；在受限环境里会报权限错误（本次审计实际遇到）。建议加 `--tmpdir` 参数或 `PYTHONPYCACHEPREFIX`，让 Windows 开发机也能跑。
5. **离线测试跑过了**：`scripts/test_geomnav.py` 8/8、`scripts/test_i18n.py` 9/9。`regression.py` 的 6/10 失败全部是沙箱写权限导致，不是逻辑失败。
6. **`dist/` 被 `.gitignore` 忽略但又存在于工作区**，且带 `dist/index.js.map`（2MB）。打包脚本只拷 `index.js`，没问题；但地图文件会让人误以为要发布。
7. **`__pycache__`（cpython-313）在插件目录里**，`build_zip.py:93` 已排除 `__pycache__`/`*.pyc`，打包安全。
8. **CDP 脚本（`scripts/cdp_*.py`）是实机专用**，没有文档说明怎么用；建议在 `CONTRIBUTING.md` 里补一段"如何用 CDP 复现焦点问题"，这对后续维护这套导航很关键。
