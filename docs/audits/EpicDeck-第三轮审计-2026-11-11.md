## 3. 代码审计

### 3.1 【P1】`tsc --noEmit` 3 条错 —— CI 现在必红

```
src/fullscreen.tsx(2742,5): error TS2322: Type '(b: number) => boolean' is not assignable to type '(_b: number) => false'.
src/fullscreen.tsx(2746,5): error TS2322: ...
src/fullscreen.tsx(2750,5): error TS2322: ...
```

原因：beta.7 的"调试钩子不再有缝隙"改法里

```ts
const hooksRef = useRef({
  nav: (_b: number) => false,     // TS 把返回类型推断成字面量 false
  navRC: (_b: number) => false,
  bump: (_d: number) => false,
  tab: (_d: number) => {},
});
hooksRef.current = { nav: (b) => { … } /* 返回 boolean */ };   // ← 这里炸
```

修复（显式标注 ref 类型，1 处）：

```ts
type Hooks = { nav: (b: number) => boolean; navRC: (b: number) => boolean; bump: (d: number) => boolean; tab: (d: number) => void };
const hooksRef = useRef<Hooks>({ nav: () => false, navRC: () => false, bump: () => false, tab: () => {} });
```

**注意**：`pnpm build`（rollup）不做类型检查，所以 beta.9–11 是"带着类型错误构建成功并部署"的；CI 的 `pnpm exec tsc --noEmit` 会红。这类错误上一轮刚用 tsc 抓到过 `DIR_UP` 未 import，说明 CI 的类型关卡是有效的，只是这次发版前没跑。

### 3.2 【P1】下载空态按钮全宽（同 V3）

`fullscreen.tsx:1380-1387` 的 `<Focusable className="ed-action" style={{ padding: "8px 16px", marginTop: "14px" }}>` 是块级 flex，没有宽度约束 → 撑满 772px。改 `width: fit-content; margin: 14px auto 0`。

### 3.3 【P2】取消下载后 `install_snapshots` 不清 → "已取消"的任务重载后复活

beta.8 加的 `install_snapshots` 只在 `paused` / `error` 时写入、`install()`（1823）和 `done`（1886）时清除。但 `cancel_install`（`main.py:2403-2459`）和 `uninstall`（2362）都没有调用 `_forget_terminal`。

后果：暂停 → 在下载页点「取消」→ 半成品目录被删、`.resume` 被删 → 重载插件后，`get_active_installs` 仍把 7 天内的 paused 快照合并进来，下载页又出现一行「已暂停 / 继续」，点继续会从零开始重新下载。

修复：在 `cancel_install` 返回前和解压/卸载路径里加 `self._forget_terminal(app_name)`；另外 `get_active_installs` 合并快照时也按 `ts` 过滤一次（现在只在写入时裁剪）。

### 3.4 【P2】`library_patch` 每个事件都写 localStorage + 全量重渲染

`store.ts:249-266`：每个 patch（后端每发现一款游戏的标题/体积就发一次）都会

1. `state.games.map()` 生成新数组；2. `setPluginState` → 所有订阅者重渲染；3. `writeLibraryCache` → `JSON.stringify(148 款)` + `localStorage.setItem`（同步，跑在 Big Picture 的 UI 线程上）。

冷启动补标题+体积时可能是几百次。建议：把缓存写入做 1s trailing 防抖（或只在 `library_full` / 页面隐藏时落盘），patch 事件按动画帧合并成一次 `setPluginState`。

### 3.5 【P2】`usePluginState()` 全量订阅

`store.ts:176-178` 订阅整个 state；`install_progress` 每秒 1–2 次 → FullScreenPage、LibraryTab、15 个 tile、详情页全部重渲染。Deck 的 CPU 不宽裕，下载时拖页面会掉帧。建议：`useSyncExternalStore` 加 selector（`progress[appName]`、`games` 分开订阅），或至少 `React.memo(LibraryTile)`。

### 3.6 【P2】12 个手写 `<Focusable className="ed-action">` 与 `ActionButton` 重复

`fullscreen.tsx:1184/1194/1208/1219/1230/1386/1402/1442/1454/1470/1482/1497` 都是手写按钮：各自实现 300ms 防抖（`once()`/`guardRef`）、各自决定 `onClick`/`onActivate`、大多漏了 `noFocusRing`。这正是 V2 视觉不一致的根源。统一成 `components.tsx` 的 `ActionButton`（已支持 `disabled`/`primary`/`danger`/`noFocusRing`/300ms 去重）可以一次消掉十几个重复点。

### 3.10 【P3】一处观感稳健性：锁屏状态下重载后，缩放可能停在 0.95

实测时间线：19:28 插件重载（当时屏幕被屏保盖住）→ 19:40 量到 `font-size: 15.2px`（scale 0.95，应为 16px），而 `.ed-surface` 的实际高度是 534 → 说明 `useViewport` 的 state 是在一次"高度 507"的测量后停住了；19:41 我强制触发一次 ResizeObserver 后恢复 16px。

推测是页面在**不可见/被遮挡**时挂载，ResizeObserver 的通知被推迟，之后尺寸变化没有被补发。建议 `useViewport` 除了 ResizeObserver，再监听 `resize` 与 `visibilitychange`，并在挂载后 300ms / 1s 各补测一次（3 行）。这不是每台设备都会遇到，但"重载后整体小了 5%"很难被用户描述清楚。
