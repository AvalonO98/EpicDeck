# EpicDeck 0.9.2 代码审查报告

审查对象：`D:\DeepSeekHarenes\_extract`（从 `EpicDeck-项目源码-20261106.tar.gz` 解出，`package.json` 版本 0.9.2）
审查范围：后端 `main.py` + `py_modules/`，前端 `src/`，构建/发布脚本与文档。
审查重点：操作逻辑、状态一致性、Steam Deck 手柄/大屏交互、页面布局、安全与隐私。

## 结论

整体质量明显高于一般的 agent 生成项目：模块边界清楚，VDF 写入有解析/回读/备份保护，安装下载有断点与外部进程接管，日志做了凭据脱敏，i18n 覆盖率高，注释也解释了大量“为什么这样做”。

但目前仍有 3 个会直接影响首次使用的问题：**浏览器登录抓旧码**、**ProtonDB 对多数游戏不可用**、**未登录时无法进入设置/诊断**。此外还有若干数据安全风险（无确认卸载/取消下载、云存档直接覆盖、取消下载时的目录删除规则过宽）和 Steam Deck 交互习惯问题（聚焦即切页、详情页 B 返回后焦点丢失、最后一页封面被拉伸）。

## 二、P0：会直接毁掉体验或造成数据损失

### 1. 浏览器自动登录仍可能抓到上一次的旧授权码；提示时间也与实现不一致

证据：

- [`main.py:78`](_extract/main.py#L78) 定义 `_LOGIN_FIRST_CAPTURE_DELAY = 20.0`。
- [`login.tsx:245`](_extract/login.tsx#L245) 却告诉用户“请稍等约 15 秒……然后再按 B 关掉浏览器”。
- 手动剪贴板分支会先用 `text != last_clip` 过滤（[`main.py:837`](_extract/main.py#L837-L842)），但**自动 Ctrl+A/Ctrl+C 分支没有做这个比较**：只要复制出来的文本里能提取出 32 位 code 就接受，哪怕它与会话开始时的 baseline 完全相同（[`main.py:848`](_extract/main.py#L848-L857)）。

影响：
用户按提示在 15 秒左右看到 JSON 就按 B，抓码还没开始；或者 Epic 的 redirect 页没有刷新出 JSON，自动复制到的是上次遗留的旧码。结果就是 `authorization_code_not_found`，而插件只给一句“授权码无效”，用户只能改用手机扫码。这正是 HANDOFF 7.0 记录但尚未修复的问题。

建议：

1. `begin_login` 时清空一次剪贴板，或记录 baseline 的哈希；自动复制分支必须要求 `text != baseline`。
2. 把首抓时间降到 10 秒以内，或把文案改成“等待 25~30 秒”；最稳的是在等待页加一个「已看到 JSON，立即抓取」按钮。
3. 发送 Ctrl+A/Ctrl+C 前确认当前 X11 焦点窗口属于 Steam 浏览器（目前只判断 6 秒无输入，见 [`main.py:851`](_extract/main.py#L851)）；否则可能把密码框内容复制进剪贴板。
4. 更彻底的方案：用 CDP 读取 redirect 页的 body（仓库已有 `scripts/cdp_eval.py`），不再依赖合成按键和剪贴板。

### 2. ProtonDB 徽章对大多数游戏仍然不显示；HANDOFF 里写的修法单独做还不够

证据：

- [`main.py:3083`](_extract/main.py#L3083-L3105) 的 `_protondb_title()` 依次查英文 `title_cache`、`_title_for()`（会返回中文本地化标题）、最后 `_lib_cache` 的 `title`；**完全没有使用 `source_title`**。
- [`py_modules/protondb.py:216`](_extract/py_modules/protondb.py#L216) 的搜索固定带 `l=schinese&cc=CN`，返回的候选名是中文。
- [`py_modules/protondb.py:160`](_extract/py_modules/protondb.py#L160-L180) 的相似度对“英文 query vs 纯中文名”返回 0.0（我已实际调用验证：`similarity("Hogwarts Legacy", "霍格沃茨之遗") == 0.0`）。

影响：
只要游戏的中文名是纯中文，用英文标题去中文商店搜就会失败；用户看到的只是“没有徽章”。HANDOFF 7.0b 提出的“改用 `source_title`”只能解决一半——还必须让搜索语言与 query 语言一致，否则英文标题仍然搜不到纯中文结果。

建议：

- `_protondb_title()` 优先返回 `source_title`（Epic 英文原名）。
- `search_appid()` 在 query 是英文时用 `l=english`（或同时查 `l=schinese` 与 `l=english` 两轮），再用 `_appdetails_english()` 校验 appid，避免同名/DLC 误配。
- 清掉已有的 `protondb` 失败缓存（或提供“重新查询”入口），否则用户要等 1 小时才看到修复效果。

### 3. 未登录时无法进入设置页，也就无法改代理、语言、CDN 或导出诊断日志

证据：

- QAM 在 `!auth?.logged_in` 时直接返回 `LoginPanel`（[`qam.tsx:417`](_extract/qam.tsx#L417-L421)），而“设置与账号”按钮只存在于登录后的 `QuickPanel`（[`qam.tsx:300`](_extract/qam.tsx#L300-L309)）。
- 全屏页同样先判断登录（[`fullscreen.tsx:2867`](_extract/fullscreen.tsx#L2867-L2870)），且 `SettingsTab` 的入口只靠顶栏 tab；登录失败时顶栏 tab 虽然可见，内容仍被登录页替换。
- Steam 菜单入口在 `index.tsx` 中被注释掉（[`index.tsx:49`](_extract/src/index.tsx#L49-L57)）。

影响：
这是最典型的“死胡同”：登录失败往往正是网络/代理/CDN 问题，而用户恰恰无法进入设置去修网络、切语言、重装 Legendary 或导出日志。README 里“请到设置 → 维护导出诊断日志”的指引在这种情况下不可达。

建议：

- 无论是否登录都渲染顶栏 tab；`SettingsTab` 的账号区在未登录时显示“去登录”，其余设置照常可用。
- 至少在 `LoginPanel` 底部加一个“设置 / 诊断”按钮。
- 后续完成 Steam 菜单入口。

### 4. 卸载、取消下载、重启 Steam、清缓存、覆盖云存档都没有二次确认

证据：

- 卸载按钮直接调用 `actions.uninstall`（[`fullscreen.tsx:1132`](_extract/fullscreen.tsx#L1132-L1141)、[`fullscreen.tsx:940`](_extract/fullscreen.tsx#L940-L949)）。
- “取消下载”调用 `actions.cancel`，而它固定 `delete=true`（[`fullscreen.tsx:1101`](_extract/fullscreen.tsx#L1101-L1109)、[`store.ts:567`](_extract/store.ts#L567-L579)）。
- “重启 Steam 刷新游戏库”直接 `refreshSteam()`（[`fullscreen.tsx:1880`](_extract/fullscreen.tsx#L1880-L1888)）。
- “清理下载缓存”直接 `clearDownloadCache()`（[`fullscreen.tsx:1984`](_extract/fullscreen.tsx#L1984-L1994)）。
- 云存档“下载云端存档”直接覆盖本地（[`fullscreen.tsx:1210`](_extract/fullscreen.tsx#L1210-L1230)）。
- QAM 的“切换 / 登出”也是单击立即执行（[`qam.tsx:280`](_extract/qam.tsx#L280-L287)）。

影响：
手柄 A 键很容易误触；卸载会删几十 GB 游戏，取消下载会丢掉断点进度，重启 Steam 可能中断正在运行的游戏，云存档下载可能覆盖更新的本地存档。

建议：

- 卸载、取消并删除、重启 Steam、清缓存、云存档下载/双向同步、切换账号全部加 `ConfirmModal`；文案写明“会删除什么”。
- “取消”和“暂停”要在 UI 上明确区分：暂停保留断点，取消删除断点。
- 云存档下载前把本地 `save_path` 复制到带时间戳的备份目录；云端为空时直接拒绝。

### 5. 取消下载的删除逻辑过宽，存在误删大目录的风险

证据：

- `_clear_partial_download` 从 `installed.json` 取 `install_path`，只要“没有 `.egstore` 或没有 version”就 `shutil.rmtree(install_path)`（[`main.py:2244`](_extract/main.py#L2244-L2258)）。
- `installed.json` 是 Legendary 的本地文件，可能被旧版本、异常中断或手工编辑污染；代码没有校验该路径是否位于已配置的游戏目录、是否是 `/`、`$HOME`、插件目录等敏感位置。
- `cancel_install(delete=True)` 在 `proc.terminate()` 后**没有等待进程退出**就立即清理（[`main.py:2206`](_extract/main.py#L2206-L2221)），存在和 Legendary 写盘并发删除的竞态。

影响：
一个损坏/被篡改的 `install_path` 就可能让“取消下载”删掉整个 home 或其他大目录；即使路径正常，也可能因为进程还在写而删不干净或损坏文件。

建议：

- 删除前做白名单校验：路径必须位于 `get_install_dir_options()` 返回的某个根目录下，且不能是 `/`、`/home`、`$HOME`、Steam 根、插件数据根；同时要求目录里存在 `.egstore`、`__install__` 或 Legendary 的 resume 文件之一。
- 先 `await proc.wait()`（带超时），再清理。
- 记住本次 install 的 target，而不是依赖 `installed.json` 反查；这样下载早期也能准确清理。

### 6. 未加入 Steam 时点“启动游戏”会先等 3 秒，然后后台启动（没有画面）

证据：

- 后端 `launch()` 即使没有 Steam 快捷方式也会返回一个计算出来的 appid（[`main.py:2128`](_extract/main.py#L2128-L2133)）。
- 前端会先 `waitForShortcutGameId` 轮询 12×250ms，再 `RunGame`（[`fullscreen.tsx:918`](_extract/fullscreen.tsx#L918-L936)）；失败后才走 `direct=true`，而后台启动不会让 gamescope 切屏（代码注释自己写了“屏幕还停在 Steam UI”）。

影响：
用户看到“正在启动”、等 3 秒、然后听到声音但没有画面，会认为插件坏了。安装后 `auto_add_to_steam` 失败时也只写日志不提示（[`main.py:1748`](_extract/main.py#L1748-L1755)），用户不知道要先加 Steam。

建议：

- 未 `in_steam` 时，主按钮改成“添加到 Steam 并启动”，或直接提示“先添加到 Steam 才能正常启动”。
- 安装完成时如果自动添加失败，给出 toast/详情页提示，而不是静默。
- `direct=true` 只作为开发者兜底，不要在普通用户路径上自动使用。

### 7. `use_proton` / `proton_path` 设置不会重写已有启动脚本，等于对 Steam 直接启动不生效

证据：

- `set_setting` 只是写配置（[`main.py:3010`](_extract/main.py#L3010-L3012)）。
- 启动脚本只在插件加载时统一重写（[`main.py:330`](_extract/main.py#L330-L332)），或某次 `launch()` / `set_lsfg` 时重写。
- 设置页切换“Windows 游戏用 Proton 运行”只 `update("use_proton", v)` 并派发 `library-changed`（[`fullscreen.tsx:1694`](_extract/fullscreen.tsx#L1694-L1697)、[`fullscreen.tsx:1901`](_extract/fullscreen.tsx#L1901)），并不会重写 `launchers/*.sh`。

影响：
用户从 Steam 库直接启动游戏（最常见路径）时，改 Proton 开关或换 Proton 版本完全没效果，必须重启插件/Steam 才生效；反过来，关掉 Proton 也可能因为旧脚本仍然带 `--wine` 而继续走 Proton。

建议：

- 在 `set_setting` 里识别 `use_proton` / `proton_path`，调用 `_sync_launcher_scripts()`；或前端再调一个 `sync_launchers` callable。
- 同时这个设置根本不需要触发整库重新拉取，见第 12 条。

### 8. 暂停后恢复不再传原安装目录；取消下载也不一定能清掉半成品

证据：

- `resume_install` 只 `install(app_name, install_dir)`，而 UI 的 `actions.resume(appName)` 不传目录（[`main.py:2229`](_extract/main.py#L2229-L2233)、[`store.ts:594`](_extract/store.ts#L594-L606)）。如果安装时用了 SD 卡/自定义目录，恢复时会回落到全局默认目录。
- `_clear_partial_download` 只有在 `installed.json` 有记录时才删 `install_path`；下载早期通常还没有这条记录，所以半成品目录可能原样留下，只删了 `.resume`（[`main.py:2244`](_extract/main.py#L2244-L2258)）。

影响：
“暂停续传”在最需要它的自定义目录场景下失效；取消下载后磁盘空间没有释放，用户下次安装可能遇到“空间不足”。

建议：

- 在配置里记录 `app_name -> install_dir`（安装开始时写入），`resume_install` 必须传回原目录。
- 清理逻辑改为使用记录下来的 target + Legendary resume 文件，而不是只靠 `installed.json`。

## 三、P1：重要逻辑与健壮性问题

### 9. 新购买/新加入的游戏不会补体积、中文名和 Steam 封面，直到插件重载

- `_ensure_metadata_refresh` 只要 `_meta_locale` 相同且 `_meta_done` 为真就直接返回（[`main.py:1374`](_extract/main.py#L1374-L1376)）。`_meta_done` 在首次全量抓取后一直为真，后台刷新新增游戏时不会为新条目补数据。
- `_ensure_image_cache` 整场只加载一次（[`main.py:2333`](_extract/main.py#L2333-L2341)），新游戏的 `key_images` 不在缓存里，`add_to_steam` 会拿不到封面。

影响：新买的游戏长期显示“体积读取中/未知”，加进 Steam 也没有封面，用户只能重启插件。建议在 `_fetch_library` 里比较 app_name 集合，发现新增就重置 `_meta_done` 和 `_image_cache`；或按 app 记录已处理的元数据。

### 10. 强制刷新被取消时可能丢掉 `entitlements.json`

`legendary.list_games(force=True)` 先把 `entitlements.json` 移到 `.old`，成功后删除备份；但 `except` 只捕获 `LegendaryError`，`finally` 无条件删除备份（[`py_modules/legendary.py:493`](_extract/py_modules/legendary.py#L493-L525)）。如果刷新任务被取消（插件重载会 cancel `_lib_task`），`entitlements.json` 仍是缺失状态，备份却被删掉。

影响：下次 `legendary list` 可能拿不到拥有列表，需要重新登录/重新拉取。建议在 `finally` 里判断 `ent` 是否存在，不存在就恢复备份（包括 `CancelledError` 路径）。

### 11. 启动参数里有未闭合引号会永久卡住“启动游戏”按钮

`_write_launcher_script` 用 `shlex.split(extra)`（[`main.py:2630`](_extract/main.py#L2630-L2633)），未闭合引号会抛 `ValueError`；`launch()` 只捕获 `LegendaryError` 和 `OSError`（[`main.py:2159`](_extract/main.py#L2159-L2162)），所以 Decky callable 直接 reject。前端 `doLaunch` 没有 `try/finally`（[`fullscreen.tsx:901`](_extract/fullscreen.tsx#L901-L938)），`busy="launch"` 永远不会复位，按钮一直显示“正在启动…”。

建议：`set_launch_args` 保存前先 `shlex.split` 校验并返回错误；`launch` 也捕获 `ValueError`；前端所有异步动作统一 `try/finally` 复位 `busy`。

### 12. 设置项触发了不必要且昂贵的整库深刷新

`update()` 对 `title_locale` / `third_party_titles` / `ui_language` / `auto_fetch_size` / `use_proton` 都派发 `library-changed`（[`fullscreen.tsx:1689`](_extract/fullscreen.tsx#L1689-L1697)），而 `reloadGames()` 固定调用 `listGames(true)`（[`store.ts:442`](_extract/store.ts#L442-L447)）。`force=true` 会重新拉 entitlement，约 20 秒网络请求。

影响：只是切换 Proton 开关或界面语言，就会看到“正在刷新游戏库…”并阻塞刷新；`use_proton` 本身还根本不需要重拉库。建议区分“重新拉元数据”和“重新拉拥有列表”，只有真正改语言/标题时才刷新列表；`use_proton` 改为重写 launcher。

### 13. 刷新/启动/安装的异常路径会让 UI 永久停在“进行中”

- `refreshLibrary` 没有 `try/finally`，`authStatus` 或 `listGames` reject 时 `refreshing` 永远为 true（[`store.ts:453`](_extract/store.ts#L453-L480)）。
- `boot()` 没有整体 `catch`，任一 callable reject 时 `booted` 永远为 false（[`store.ts:297`](_extract/store.ts#L297-L440)），已登录用户可能被当成未登录。
- `doInstall` / `doUninstall` / `doToggleSteam` / `doCloudSync` 同样没有 `try/finally`。

建议：所有 UI 动作包 `try/catch/finally`；boot 失败时设置 `booted=true` 并显示可重试错误；刷新加 in-flight guard，按钮在 `refreshing` 时禁用。

### 14. 离开二维码页不会停止手机登录 HTTP 服务；剪贴板错误会回显内容

- 进入扫码页会启动 0.0.0.0:8899 的本地服务（[`login.tsx:128`](_extract/login.tsx#L128-L132)），但“返回”只 `setShowCode(false)`（[`login.tsx:434`](_extract/login.tsx#L434-L441)），没有 `stopLogin()`；服务会一直开到 600 秒超时。期间手机若提交授权码，Deck 会被登录。
- `login_with_clipboard` 失败时把剪贴板前 80 个字符拼进错误消息（[`main.py:640`](_extract/main.py#L640-L646)），会显示在 QAM 上。剪贴板里如果是密码/私聊内容，就被暴露在屏幕上。
- 自动抓码的 Ctrl+A/Ctrl+C 在密码框聚焦且用户停手 6 秒时，可能把密码复制进剪贴板（见第 1 条）。

建议：离开扫码页/组件卸载时调用 `cancelLogin()`；错误消息只提示“未识别到授权码”，不要回显内容；合成按键前校验焦点窗口，或改用 CDP。

### 15. 云存档同步没有本地备份/空存档拦截

`sync_cloud_saves` 直接调用 `legendary sync-saves`（[`main.py:3116`](_extract/main.py#L3116-L3130)），没有先备份本地 `save_path`，也没有检查云端是否为空。NOTICE 里提到参考了 GameBridge 的“覆盖前备份/空存档拦截”，但代码里没有实现。

`--accept-path` 会接受 Legendary 推断的路径，在 Proton 前缀路径发生变化时可能同步到错误目录。建议：下载/双向同步前复制 save 目录到 `save_path + ".epicdeck-backup-<ts>"`，云端为空时拒绝，并在 UI 明确显示将覆盖哪个目录。

### 16. 导出诊断日志会带上完整配置、游戏库和游玩时长

`export_logs` 把 `self.config._data` 全部写进日志（[`main.py:3466`](_extract/main.py#L3466-L3470)），其中包括 `title_cache`、`playtime_cache`、`size_cache`、`first_seen`、`protondb`；还有未脱敏的 `display_name`（[`main.py:3461`](_extract/main.py#L3461)）和用户路径。文件里写着“已脱敏”，实际只脱敏了 account id。

建议：白名单输出 `install_dir`、`legendary_path`、`use_proton` 等排障必需项；省略大缓存和游戏名/时长；显示名做 mask；明确告诉用户导出内容包含哪些信息。

### 17. 下载过程中仍可“清理下载缓存”；切换账号会清空整个 Steam 浏览器数据

- 设置页“清理下载缓存”始终可点（[`fullscreen.tsx:1984`](_extract/fullscreen.tsx#L1984-L1994)），后端也没有检查 `get_active_installs()`；下载中清理 `tmp` 会破坏断点。
- `switchAccount` 调 `SteamClient.Browser.ClearAllBrowsingData()`（[`store.ts:491`](_extract/store.ts#L491-L505)），会清掉所有站点的 Cookie/缓存，不只是 Epic；可能把 Steam 商店/网页登录态一起清掉。

建议：有活动下载时禁用清理；切换账号只清 Epic 域名 Cookie（Steam 没有公开作用域 API 时，至少明确提示会清空浏览器数据）。

### 18. 卸载游戏不会移除 Steam 快捷方式/封面；首次运行提示会在升级后重现

- `uninstall()` 只调用 `legendary uninstall`（[`main.py:2191`](_extract/main.py#L2191-L2196)），Steam 条目仍在，点“开始游戏”会立刻退出；grid 封面也留在磁盘。
- `first_run_done` 默认 `False`（[`py_modules/config.py:23`](_extract/py_modules/config.py#L23)），老版本配置没有这个 key，升级后即使用户已有安装目录也会再弹一次“先选下载位置”（[`store.ts:325`](_extract/store.ts#L325)）。

建议：卸载后询问“同时从 Steam 移除？”或在详情页给出明确入口；首次运行判断 `install_dir`/已安装游戏存在时视为已完成。

## 四、交互与页面适配（Steam Deck 使用习惯）

### 19. 游戏库最后一页的封面会被拉成整屏高

网格行数按当前页游戏数计算：`repeat(ceil(pageGames.length / cols), minmax(0, 1fr))`，同时容器 `height: 100%`（[`fullscreen.tsx:655`](_extract/fullscreen.tsx#L655-L674)）。138 个游戏、每页 15 个时，最后一页只有 3 个，行数 = 1，这一行会占满整个内容高度，封面被 `objectFit: cover` 裁成细长条。

建议：固定 3 行（`repeat(3, minmax(0, 1fr))`）或给 tile 设 `aspect-ratio`，并让网格 `alignContent: start`；最后一页留白比拉伸好看。

### 20. 详情页按 B 返回后，第一下手柄方向键可能没反应

打开详情页时会把焦点放到主按钮（[`fullscreen.tsx:2345`](_extract/fullscreen.tsx#L2345-L2357)），但 B 返回只是 `setDetail(null)`（[`fullscreen.tsx:2671`](_extract/fullscreen.tsx#L2671-L2675)），没有把焦点还给对应的封面。`remembered` 仍指向已卸载的按钮，`currentFocused()` 找不到可用的 DOM 焦点时 `moveFocus` 返回 false，而方向键又被无条件 `preventDefault`（[`fullscreen.tsx:2569`](_extract/fullscreen.tsx#L2569-L2575)），于是第一次按键被吞掉。

建议：详情页关闭时 `focusOwned` 对应游戏的封面（需要把 app_name 传回 LibraryTab），或至少聚焦“返回/游戏库”按钮。

### 21. “聚焦即切页/切筛选”不符合 Steam 的操作习惯，而且有副作用

- 顶栏 tab 带 `data-ed-focus-action`，光标落到哪个 tab 就切到哪个页面（[`fullscreen.tsx:2713`](_extract/fullscreen.tsx#L2713-L2721)、[`fullscreen.tsx:2359`](_extract/fullscreen.tsx#L2359-L2374)）。
- 筛选 chip 同样“聚焦即应用”（[`fullscreen.tsx:529`](_extract/fullscreen.tsx#L529-L544)）。

影响：

- 想从“游戏库”滑到“刷新”时，会依次经过“下载”“设置”，每次都真的挂载/卸载页面；`SettingsTab` 一挂载就发 6 个后端调用（[`fullscreen.tsx:1661`](_extract/fullscreen.tsx#L1661-L1681)），包括 `checkUpdate`、`getProtonOptions`、`getLsfg` 等。
- 想从筛选行滑到搜索框，途中会逐个应用“全部/已安装/未安装”，用户可能没意识到筛选被改了。
- Steam 自己的 UI 是“移动焦点 → A 确认”，这里变成“移动焦点即执行”，手柄很容易误操作。

建议：至少把 tab 和筛选改成 A 键确认；如果确实想保留“聚焦即切页”，不要用它来挂载有网络请求的设置页，并给筛选加 300ms 防抖/只在 A 时应用。

### 22. 设置页会在 900ms 内反复把焦点抢回“切换账号”

`SettingsTab` 打开后会在 40/220/420/900ms 连续调用 `settle()`，每次都 `focusOwned(first)`（[`fullscreen.tsx:1637`](_extract/fullscreen.tsx#L1637-L1640)）。用户如果很快开始移动焦点，会被反复拉回。建议只在首次渲染/滚动复位时抢一次，并检测当前焦点是否已被用户移动。

### 23. 字体整体偏小、返回语义不一致

- `viewport.scale` 最小 0.82，根字号 16px（[`viewport.ts:46`](_extract/src/viewport.ts#L46)），页面上大量 0.72~0.8em 的提示只有 12~13px；7 寸屏上偏小。
- 详情页顶部的“返回”退出整个插件，而详情内部另有一个“游戏库”按钮返回列表（[`fullscreen.tsx:973`](_extract/fullscreen.tsx#L973-L980)）；用户按“返回”可能预期回列表。

建议：把次要文字下限提到 0.85em 左右；详情页顶部按钮改成“退出/关闭”或与 B 行为一致。

## 五、安全与隐私

1. **TLS 校验回退到 `CERT_NONE`**：`legendary_installer._ssl_context` 在 certifi 和系统 CA 都不可用时直接关闭证书校验（[`py_modules/legendary_installer.py:80`](_extract/py_modules/legendary_installer.py#L80-L83)）；而 `epic_api` 复用它发送 Bearer token（[`py_modules/epic_api.py:19`](_extract/py_modules/epic_api.py#L19)）。虽然正常 SteamOS 有系统 CA，但“验证失败就关验证”不应作为兜底；带 token 的请求必须 fail closed。
2. **Epic token 文件权限**：`auth_with_code_native` 用默认 `open(..., "w")` 写 `user.json`（[`py_modules/legendary.py:374`](_extract/py_modules/legendary.py#L374-L381)），在常见 umask 022 下是 0644，同机其他用户可读 refresh token。建议 `os.chmod(path, 0o600)`。
3. **`app_name` 未做路径字符校验**：它来自 Epic 返回的 `app_name`，但直接拼进 `launchers/<app_name>.sh`、`proton/<app_name>.sh`、`logs/install-<app_name>.log`（[`main.py:2501`](_extract/main.py#L2501)、[`main.py:2588`](_extract/main.py#L2588)）。建议只允许 `[A-Za-z0-9._-]+`（代码在 `_scan_external_installs` 里已经这么做了，写入路径也应一致）。
4. **多账号下 shortcuts 目录选择**：`steam._config_dir` 按 `shortcuts.vdf` + mtime 打分选账号目录（[`py_modules/steam.py:230`](_extract/py_modules/steam.py#L230-L265)），多个 Steam 账号时可能把快捷方式写到非当前账号。建议读 `registry.vdf` 的 ActiveUser，或用 Decky/Steam API 取当前用户。
5. **文档与实现不一致**：`SECURITY.md` 说“唯一硬编码常量是公共客户端 ID、不含密钥”（[`SECURITY.md:7`](_extract/SECURITY.md#L7-L15)），但 `legendary.py` 里还有 `EPIC_LAUNCHER_SECRET`（[`py_modules/legendary.py:80`](_extract/py_modules/legendary.py#L80-L81)）。它是 Legendary 的公开客户端密钥，不是用户密钥，但文档应准确说明。

## 六、工程、发布与文档

1. **CI 不跑测试**：`.github/workflows/release.yml` 只有 build/package，没有 `scripts/regression.py`、`tsc --noEmit` 或测试；`package.json` 的 `test` 还是 `exit 1`（[`package.json:10`](_extract/package.json#L10)）。建议 CI 加 `pnpm install && python3 scripts/regression.py` 和 `pnpm exec tsc --noEmit`，并修掉 `pnpm test`。
2. **说明与实际大小不符**：UI 和 README 说 Legendary 约 3 MB（[`qam.tsx:61`](_extract/src/qam.tsx#L61)、[`fullscreen.tsx:2845`](_extract/fullscreen.tsx#L2845)），但 `legendary_installer.py` 注释自己写的是约 14 MB（[`py_modules/legendary_installer.py:43`](_extract/py_modules/legendary_installer.py#L43)）。
3. **`Config` 默认值浅拷贝**：`dict(DEFAULTS)` 只复制第一层（[`py_modules/config.py:102`](_extract/py_modules/config.py#L102)），`first_seen`、`title_cache` 等嵌套 dict 会被不同 `Config` 实例共享。我实际验证过：修改一个实例的 `first_seen` 会影响模块级 `DEFAULTS` 和后续实例。建议 `copy.deepcopy(DEFAULTS)` 或加载时补默认值时复制。
4. **死代码/死配置**：`refresh_token_managed`、`auto_protondb` 没有使用；`getProtonDbCached`、`activeLabel`、`find_game`、`remove_game`、`open_login_browser` 无调用；`show_menu_entry` 的 UI 被隐藏。建议清理或补完，避免后续维护误判。
5. **一处未翻译 JSX 文本**：`日志已导出到:` 是裸文本（[`fullscreen.tsx:2106`](_extract/fullscreen.tsx#L2106)），英文界面会显示中文；项目的“未包裹中文”检查只扫描字符串字面量，漏掉了 JSX text。
6. **发布流程**：workflow 对所有 `v*` tag 都 `prerelease: false`；如果发布 beta tag，`/releases/latest` 可能把 beta 当稳定版推给用户。建议 `prerelease: contains(github.ref_name, '-')`。
7. **第三方许可证**：`dist` 里打包了 `qrcode`、`react-icons` 等 MIT 依赖；`NOTICE` 只列了名称/许可证，没有随包附带 MIT 版权声明。发布前建议核对 `NOTICE`/`LICENSE`。
